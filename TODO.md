## Bugs

- [x] **Multi-tab / multi-window local DB conflict (web).** Opening the app in two browser tabs/windows at once broke the local store — `wa-sqlite` uses OPFS, which is single-writer per origin, so the second tab couldn't acquire the DB. Shipped: `useWebDbLock` gates `SQLiteProvider` behind an exclusive `navigator.locks` request (no-op on native); a second tab renders `DbLockedScreen` instead of crashing, and picks up automatically — no polling — once the first tab closes, since the Locks API queues the waiting request and resolves it when the holder releases.
- [x] **Armour Points auto-fill counted unequipped armour.** `armourPointsByLocation` summed AP from every armour item regardless of `equipped`. Shipped: skips unequipped items.
- [x] **Armour location matching didn't recognize Spanish location names.** `normalizeLocation` only matched English substrings ("Head", "Left Arm"...), so Spanish-content or manually-entered Spanish armour locations (e.g. "Cabeza", "Brazo izq.") contributed 0 AP everywhere. Shipped: synonym-table matcher (`LOC_SYNONYMS`) covering English + Spanish, structured so more languages can be added later.

## Near-term features

Realistic next picks — small enough to actually finish in a weekend or two, with clear success criteria.

- [x] **WFRP container capacity (homebrew).** Backpacks, sacks, sling bags, saddlebags etc. carry a `capacity` field; when equipped, capacity is added to the carrier's max encumbrance. Layers on top of the existing −1 Enc for equipped items — Backpack (Enc 2, cap 2) equipped gives −1 carried + 2 max = net +3 usable capacity. **Not RAW** (Core WFRP 4e doesn't have a capacity mechanic on containers), but a common house rule and a natural extension of the equipped-items model. Shipped: `capacity?: number` on `WfrpTrapping`; `encumbranceMaxValue` sums equipped containers' capacity via a private `containerCapacityBonus` helper; Capacity input + `Cap +N` badge in Trappings UI; static `defaultContainerCapacity()` lookup prefills known containers from "Search the book"; i18n keys `wfrp.trappings.capacity`/`capacityHint`/`capacityBadge`. Plan: `docs/superpowers/plans/2026-07-01-wfrp-container-capacity.md`.
- [x] **WFRP manual roll entry (replaces opposed-test dice mode).** Dropped in favor of a calculator-style flow — most players roll physical dice and just want the app to compute the result. Shipped: the roll number in `WfrpRollModal` is tappable and becomes a numeric input (1–100); confirming recomputes SL/success/crit/fumble via the already roll-agnostic `evaluateWfrpTest`. Difficulty chips now recompute against whichever roll is showing (virtual or typed) instead of re-rolling; "Roll Again" still generates a fresh virtual roll. `useWfrpRoll` gained `setManualRoll`.
- [x] **Spanish range/duration for book spells.** ES content overlay only carried translated `name` for spells; `range`/`duration` fell back to English. Shipped: all 579 book spells now carry Spanish `range`/`duration` (seed `es-6`), generated by `scripts/translate-spell-es.mjs` (phrase map + token rules, with a data test guarding against untranslated leftovers).
- [x] **Special-roll animations (WFRP4e RAW auto bands + doubles + Chaos flair).** Dice engine now implements 01–05 always-success / 96–00 always-failure (RAW, independent of target); `WfrpRollModal` adds flair for chaos (roll 88, purple + shake + caption), crit (gold + bigger bounce), fumble (shake), and auto-success/auto-failure (captions), fully bilingual.
- [x] **WFRP roll special effects — crumble, halo, chaos flames.** Fumble/auto-failure (and failed 88s) crumble the roll card into falling shards (Reanimated, code-only — no assets); crit/auto-success float a golden halo above the card; any 88 burns purple chaos flames behind the content (flames mark the number, not the outcome — a successful 88 doesn't crumble). Lottie overlays use hand-authored placeholder JSONs in `src/assets/lottie/` — swap the files to upgrade the art, no code change. Sound architecture shipped silent: `src/lib/sound.ts` stub + `sound_enabled` setting + Settings toggle, wired end-to-end for future expo-audio clips. Verified working under production COOP/COEP web build and native (iOS) bundle export. Plan: `docs/superpowers/plans/2026-07-14-wfrp-roll-fx.md`.
- [x] **Translatable characteristic abbreviations.** `CHARACTERISTIC_ABBREV` was hardcoded English-only (WS/BS/S/T/I...); Spanish players saw English abbreviations everywhere. Shipped: i18n `wfrp.char.*` keys, ES uses Devir abbreviations (HA/HP/F/R/I/Ag/Des/Int/V/Em).
- [x] **Backend hardening — schema-as-code, RLS verification, account deletion.** Supabase schema and RLS policies are now version-controlled via the Supabase CLI (`supabase/migrations/`), with pgTAP tests (`supabase/tests/rls_characters.sql`, run via `npm run test:db`) proving cross-user isolation. Account deletion — required by App Store Guideline 5.1.1(v) — ships as two distinct actions in `AccountSheet`: "Remove cloud data" (reversible soft-delete of cloud rows, local characters untouched) and "Delete account" (permanent, via a new `delete-account` Edge Function that hard-deletes the auth user; character rows cascade). Plan: `docs/superpowers/plans/2026-07-30-backend-hardening.md`.
- [x] **Beta readiness — D&D beta badge, bug-report tab, translated confirm dialog.** D&D 5e is marked `Beta` in the create-character system picker so testers know it trails WFRP. A Report tab (`app/(tabs)/report.tsx`) lets testers file bugs, wrong-content reports, and suggestions into a write-only `bug_reports` Supabase table — anonymous submission allowed, with the RLS policy (`user_id is null or user_id = auth.uid()`) rejecting forged user ids, since a column default alone does not stop a client from supplying its own value. Reports capture app version, platform, and locale automatically. The tab hides when Supabase is unconfigured. Also fixed: `confirmRemove` hardcoded English "Cancel"/"Remove"/"Remove?" in the native alert on all 19 call sites — now translated (web is unaffected; `window.confirm` labels are browser-supplied). Plan: `docs/superpowers/plans/2026-08-07-beta-readiness.md`.

- [ ] **Armour diagram visual polish.** Shipped 2026-08-29 with simple flat shapes (circle head, trapezoid torso, rectangle limbs) — a first pass using opengym's muscle-atlas art didn't look right once rendered, so it was swapped for this. ## Wiki — no plan yet

The "wiki" the app has today is [`WikiModal.tsx`](src/components/wfrp4e/WikiModal.tsx) — a tap-to-view popup for user-entered descriptions on a talent / skill / spell row, plus the "Search the book" autocomplete backed by [`src/data/wfrp-content/`](src/data/wfrp-content/). A standalone browsable rulebook wiki (open anytime, not just per-row) has never been specced. If it happens, first decision is whether it browses the same C7-permitted JSON already used by the autocomplete or a richer curated dataset — the latter has licensing implications.
